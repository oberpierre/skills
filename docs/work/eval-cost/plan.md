# eval-cost

**Branch:** `improvement/eval-cost`

**Issue:** #48

Cut what the eval suite costs, so that `build`'s end-of-feature run, and every run after it, fits the five-hour budget. Recorded runs put a live build at $0.45 to $0.75 per run and a refusal at $0.05 to $0.07. The 63 `build-*` cases, run as they stand, would cost about $25, which is about eight five-hour windows at `EVAL_BUDGET_USD=3`. A run is the expensive part and a grader costs nothing, so the saving comes from fewer live runs carrying more graders each.

## Decision log

- In evals, `challenge` runs on sonnet whenever the case runs on sonnet. `evals/run.sh` exports `ANTHROPIC_DEFAULT_OPUS_MODEL` set to the full sonnet model id, `claude-sonnet-5-5`, only for a case whose `# model:` line is `sonnet`, and unsets it for any other case, so the `opus` alias in `challenge`'s frontmatter resolves to sonnet there and a value in the caller's shell never reaches an opus case. The skill text is unchanged, and the `challenge-*` cases, which run on opus, keep testing it on opus. Observed on CLI 2.1.330 with a probe skill holding `context: fork` and `model: opus` on a haiku session: the fork ran on `claude-opus-5-5` without the variable and on `claude-haiku-5-5` with it set to that model id. An alias was never observed to work, so the id is pinned. Rejected: `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, which forces every subagent and not only the `opus` alias, and a `challenge_model` config key, since a skill cannot apply a model from config to itself.
- An ending that follows a slice being built, such as the slice's stop, its issue closing or the challenge's defects going back to the coding agent, is graded on the live build its case is merged into. Only `close` and list cases start from every row `done`, and they already do. A case uses a recorded session (`history_file`) only where the ending needs the conversation, such as the queue of questions, since a recording costs replay tokens and needs `refresh-history.py` whenever the skill text changes.
- `evals/run.sh --changed <base>` runs, one run each, every case of every skill whose `skills/<skill>/` folder differs from the merge-base with `<base>` (`git diff <base>...HEAD`), a case belonging to a skill by its `evals/<skill>-*` name with the hyphen, so `grill` never takes `grilling-*`. The merge-base keeps commits made on `<base>` after branching from running cases they alone changed. It checks the five-hour budget before every case and stops the loop once it is reached, since one `build` change runs every `build-*` case. Each case gets its own model routing, so the sonnet routing never carries into a later opus case. The full suite runs only before a release tag. A feature runs `--changed` against the branch it started from. The pending end-of-feature run of `build` still covers every `build-*` case, after they are merged.
- Cost comes first: two cases stay separate only when their setups cannot share one run, and a separation that would merely be nice to have does not justify a run. A merged case grades each property its parts graded, with graders independent of each other, so one early miss does not zero the rest. It may raise `timeoutSeconds` to 600. A grader keeps the prompt form and the config keys its own behaviour depends on: issue-closing graders keep `/build S<n>` or `/build <plan>`, since issues close at a different point in each, while a commit-style grader depends on the style and not on how the build was started. A case is removed when a case that stays grades everything it graded.
- S3 merges or removes exactly these cases:
  - `build-builds-a-slice-out-of-order`, new, from `build-builds-one-slice`, `build-builds-out-of-order`, `build-closes-slice-issues` and `build-runs-e2e-before-the-challenge`: `/build S3` from the default branch with an uncommitted plan, S1 and S2 `todo`, `arlo-features`, `tracker: github`, `e2e` set, a 600-second timeout.
  - `build-reads-its-arguments` takes `build-follows-the-conventional-style` and `build-follows-a-repo-style`: `/build shipping-notes S3` with two plans under a repo style extending `conventional`. Loading a preset by name stays pinned by the `plain`, `arlo` and `arlo-features` cases.
  - `build-builds-the-whole-feature` takes `build-follows-the-plain-style`, running under `commit_style: plain`.
  - `build-carries-out-a-rework` takes `build-closes-issues-after-a-squash`, `build-carries-out-a-rebuild` takes `build-closes-a-rebuilt-issue`, and `build-carries-out-a-revert` takes `build-closes-a-reverted-issue`, each under `tracker: github`.
  - `build-stops-on-a-bad-config` takes `build-stops-on-an-empty-gate`, `build-stops-on-a-non-string-e2e` and `build-stops-on-a-style-extending-two-levels`: an empty gate, `e2e` as a list, a style extending twice and an unknown tracker, each named.
  - `build-stops-on-missing-config-keys`, new, from `build-stops-on-a-missing-gate`, `build-stops-on-a-missing-commit-style` and `build-stops-on-tracker-github-with-gh-missing`.
  - `build-stops-on-a-table-missing-a-column` takes `build-stops-on-github-without-an-issue-column`: no `Blocked by` and no `Issue` column under `tracker: github`.
  - `build-lists-every-plan` takes `build-suggests-a-rework-slice`, `build-suggests-close-when-all-done` and `build-lists-a-broken-table`: four plans, each listed with its own suggestion or its problems.
  - `build-closes-with-a-pull-request` takes `build-reads-close-then-the-plan`, with a second plan holding open slices.
  - `build-refuses-to-close-a-reworked-slice` is removed, since `build-refuses-to-close-open-slices` refuses on and names its `rework` row, and `build-merges-locally-with-gh-missing` is removed, since a missing and a logged-out `gh` both fail `gh auth status` and `build-merges-locally-without-gh` covers that path.
  - Every other `build-*` case stays, because its setup excludes the others': `invalid-yaml`, since nothing else can be read once the YAML is broken, the other plan stops, the single-plan `lists-and-suggests`, the two remaining local-merge cases, the comment refusals, the argument and branch stops, the recorded cases, and the live builds `applies-challenge-defects` under `arlo`, `asks-a-missed-decision`, `asks-on-a-wrong-premise`, `reports-a-broken-environment` and `carries-out-a-squash-from-the-absorbed-row`.
- The work lives on `improvement/eval-cost`, branched from `feature/build`, because the `build-*` cases it reshapes exist only there. It merges back into `feature/build` with a local `--no-ff` merge before `build`'s end-of-feature run, so `build`'s pull request carries the slimmed cases. The `build` plan's rule that every case runs once at the end of the feature stands, and only the number of cases changes.
- Trimming skill text, such as `SLICE.md`, is out of scope. It saves about 10% a run, but every line is pinned by an eval.
- No slice of this feature runs a live eval. S1 and S2 are pinned by gate tests with a stub `claude`, and S3 checks each scaffold by running it locally and each grader offline against saved traces. This overrides the per-slice red/green rule in `.claude/CLAUDE.md` for this feature, as the `build` plan does for its own. One eval run, `build`'s end-of-feature run after this branch merges into `feature/build`, covers both features, since every reshaped case is a `build-*` case. That run starts with one merged case and confirms from its trace that `challenge` ran on sonnet before the rest run, because a silent failure of S1 would pay opus prices on every case after it.
- S3 is blocked by S1 for cost, not code: the end-of-feature run of its cases is a live `build`, which before S1 pays for `challenge` on opus.
- This plan is closed by hand with a local `--no-ff` merge into `feature/build`, not by `/build close`, which opens a pull request against `origin/HEAD` (`main`) whenever `gh` is logged in.
- The gate's failure message for S1's test names what broke, "run.sh routed the opus alias wrongly for a sonnet or opus case", as the gate's other messages do, while the plan keeps the test's name.
- `--changed` treats only its own budget check as the budget stop, and a case's exit 2 is recorded as a failure like any other, since the loop checks the budget itself before each case and a `claude` exit 2 must not skip the remaining cases.
- The per-case routing in a `--changed` run comes from S1's unset in each case's fresh process, so S2 adds no test that the sonnet routing never carries into a later opus case.
- A small case keeps the "`commit_style` names neither a preset nor a file" stop pinned, bringing the `build-*` cases to 43, since it is a stop `SKILL.md` lists and costs about $0.06.
- `build-stops-on-a-table-missing-a-column` checks only that `/slice` is named, not that it is tied to the missing `Issue` column, since tying it would need a less reliable `llm` judge.
- With `build-builds-the-whole-feature` under `plain`, no full-feature build exercises a rebase rebuild, and `build-carries-out-a-rebuild` alone pins it for a single slice.
- Assumption, to be overturned by the end-of-feature run: a missing `gh` takes the same local-merge path as a logged-out one, as `CLOSE.md` treats both under one branch, so `build-merges-locally-with-gh-missing` stays removed.
- The first live end-of-feature run is S3's only proof. The offline checks were run once and are not committed, since a committed scaffold test would check setups without the graders.
- A sonnet case runs its main session on `claude-sonnet-5-5` too, the id its forked `challenge` uses, so one case never runs on two models.
- This feature's commits carry no `Co-Authored-By` trailer. The user reviewed them and delivers them without it.

Note, 2026-11-22: the slicing first had a slice starting ending-only cases from a scaffold with every row `done`. `build` refuses a `done` slice and starts no coding agent then, so those endings were unreachable, and the slice was dropped. Merging was first limited to cases sharing a live build, with refusals kept separate, until the user put cost first.
