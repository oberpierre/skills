## Decision log

- The primitive is named `grilling`, as in Matt Pocock's repository. It is the name `grill`'s credit already points to, it matches the glossary's **Grilling**, and it names the discipline rather than only the format. Rejected: `rounds` and `interview`.
- `grilling` holds the **Rounds** section of `grill` with what `grill` says alongside it today: what a decision is, and that the user makes each one and the agent recommends. No line about facts is added, since `grill` has none and `grill-first-round`'s `asks-no-fact` passes without one, and the extraction is meant to change nothing. `grill` keeps the no-code rule, **Recording** and **Ending**. Every caller needs the asking, whereas where the answers go and what follows differ between `grill` (glossary, ADRs, plan) and `slice` (its decision log, the table proposed again).
- `grilling` starts with no rule for a scoped list of decisions. A called skill shares its caller's context, so the decisions a caller raised are already before the model, and Matt Pocock's `grilling` works without such a mode. A line limiting it to the given decisions is added only if its case runs red. Rejected: writing the scoped mode up front, which may be a line the model does not need.
- When nothing is open, `grilling` hands back to its caller without listing anything, and the caller lists the decisions: `grill` after writing the plan and asking the challenge's findings, as today, and `slice` under its table proposed again, so one approval confirms both. The closing line stays word for word, "…or list the decisions for you to confirm once nothing is open", and holds for both callers. `grill`'s cases pin that line, so keeping it lets them prove the extraction changed nothing.
- `grilling` takes its subject as free text in `$ARGUMENTS`, with `argument-hint: "[what to grill]"`. `grill` calls it once with the idea and once more with the challenge's findings, and `slice` once per proposal that raises open decisions, with those decisions. Later rounds go on from `grilling`'s text already in context. It matches how `grill` and `challenge` take arguments, and calling once per subject does not reload the same text every round.
- `grill`'s challenge findings round goes through `grilling` too, with the findings as its subject, and `grill` keeps its own rules for that round: titles starting `Challenge:` and "Fix as stated?". It is the same kind of scoped round `slice` needs, so one mechanism serves both, and `grill-ends-with-challenge` already pins its result.
- `grill`'s five eval cases, with their graders unchanged, prove that the extraction preserves `grill`. Unchanged graders are the strongest proof that a refactor changed nothing. The cases that resume a recording carry `grill`'s text as recorded, so whether they need re-recording rather than `refresh-history.py` is found out when they are run. Those recordings already show the old round format, so they can pass without `grilling` loading at all: `grill-first-round` and `grill-ends-with-challenge` each gain a `tool_used` grader on `Skill` matching `grilling` with `min: 1`, adding graders and changing none.
- One new case scaffolds a plan with several decisions on disk and types `/grilling` naming two of them and the plan's path, so that reading the plan puts all of it in context, checking that it asks those in the round format and nothing about the others. Like `challenge`, a model-invoked skill can still be typed, which gives `grilling` a seam of its own before `slice` uses it, and the case tests the drift a whole plan in context invites. Rejected: a recording, which would measure no lead.
- ADR 0008's list of model-invoked skills gains `grilling`, and no new ADR is written, since ADR 0008 already states how skills compose. `grilling` is also listed in `.claude-plugin/plugin.json` and gets a row in the README's skills table marked `agent or you`, which the gate requires. The `plugin.json` line will conflict with the slice branch's entry, and keeping both resolves it.
- `grilling` credits Matt Pocock's `grilling`, and `grill` credits his `grill-with-docs` instead. `grill-with-docs` wraps `grilling` and also writes ADRs and the glossary, which is what `grill` keeps after the extraction, whereas `grill-me` is the bare call. `CREDITS.md` says the same: `grilling` is built on his `grilling`, and `grill` on his `grill-with-docs` and `domain-modeling`, with the commit those were read at, checked when built since `grill-with-docs` may postdate `4ae2317`. Rejected: crediting `grill-me`.

- S1 ran red with no `grilling` skill at 0.71 on every run: no run used the round format or its closing line, and they asked only the named decisions. Without the plugin, 0.57, 0.71 and 0.71, one run also reopening other decisions. With the skill, `grill`'s Rounds section moved unchanged and no scoped-list line, 1.0 on every run against 0.62 without. `grill-first-round` stayed at 1.0 with `grilling` installed. S1 cost $1.73.
- S2 added the `calls-grilling` grader to `grill-first-round`. Run red on the old `grill`, it scored 0.88 on every run, failing only that grader. With `grill`'s Rounds section replaced by the call to `grilling`, it scored 1.0 on every run, calling `grilling` once each. The three recorded sessions predate `grilling`, so their earlier turns held the round format but no `grilling` call, and they tested `grill` with its format copied from the recording. Resumed on them, every `grill-second-round` run and two of three `grill-records-terms` runs called `grilling` afresh, and `grill-ends-with-challenge` scored 0.83 on every run, always missing the closing line, which only `grilling` now holds. Each recording gained the `grilling` call and its expanded text after `grill`'s, copied from a real run and relinked, so `refresh-history.py` keeps that text current too. On them, `grill-ends-with-challenge` scored 1.0 on every run. `grill-maps-onto-existing` gained `calls-grilling` and scored 1.0. `grill-second-round` and `grill-records-terms` gained `keeps-the-recorded-grilling`, `max: 0`, since a later round goes on from the text already loaded, and it passed on every run. `grill-records-terms` scored 0.93 and then 1.0. `grill-second-round` scored 0.96 twice, each time one judge split on `reasks-nothing-settled` over questions refining earlier answers (adding a line to Q8's text, a parameter to Q9's factory), against 1.0 on every run before the re-recording. `grill-ends-with-challenge` needs `--allow-tools Write Edit 'Bash(git:*)' 'Bash(test:*)'`, or `challenge`'s `` !`test -n … && git log …` `` line is refused and no findings come back. `grill-with-docs` and `grilling` both exist at `4ae2317`, so `CREDITS.md` keeps that commit. S2 cost $8.20 with the reruns.
